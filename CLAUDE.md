# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

MetaTrader 5 (MT5) Expert Advisor and scripts implementing a grid trading strategy in MQL5 (C++-like syntax).

**Files:**
- `FixedGrid.mq5` — Fixed-range grid EA centered on a manually configured `CenterPrice` (required, `> 0`), computed **once** at `OnInit()` via `ComputeGridBoundaries()` (snapped by `RoundCenterPips`) — there is no re-centering, so the band `[center − GridRangePips, center + GridRangePips]` (`gridLowerInt`/`gridUpperInt`, same band for buy and sell) is fixed for the whole run. `BuyEnabled`/`SellEnabled` are independent switches (no trend filter) — both grids can run simultaneously. `OnTick()` fires `RunGridManagement()` once per new `PERIOD_CURRENT` bar (`lastBarTime` gate) rather than on every tick or a one-shot `OnInit()` call — this both keeps backtests fast (heavy work isn't repeated every tick) and is self-healing (a placement rejected by a transient "market closed" at the very start of a run is retried on the next bar rather than being lost forever); grid work also runs on `OnTrade` position-close (`lastPositionCount` pattern). The active side places a ladder of pending orders `GridStepPips` apart across the band, each carrying its own 1-step (`GridStepPips`) TP so filled positions take profit one by one; levels below the market are placed as limit orders and levels above as stop orders (buy grid; mirrored for sell), so the whole band is always populated regardless of where price sits inside it. `BuyUpperLimitPrice`/`SellLowerLimitPrice` (both `0` = no cap) are optional absolute price caps applied in `ManageGrid()`: the ladder stays anchored to the center-based levels, but a buy level above its cap (or a sell level below its cap) is neither placed nor kept — the effective bound is passed to `CleanupOrders()` so out-of-cap pendings are pruned. Open positions and their TPs are unaffected. `TradingStartHour`/`TradingEndHour` (both `0` = no restriction) gate new pending-order placement only. `OnInit` rejects `CenterPrice <= 0`, negative `GridRangePips`, negative `BuyUpperLimitPrice`/`SellLowerLimitPrice`, both directions disabled, or trading hours outside 0–23. `MagicNumber` defaults to `8070`
- `CloseOnlyBasket.mq5` — The **Basket Engine Architecture** with **no entry trigger at all**: it never opens a level-0 position itself, only manages positions that already carry its `MagicNumber` (default `8020`) — however they were opened (manually, by a script, or handed off from another EA). Filtering is by `MagicNumber` alone (symbol + magic + direction, same as the shared engine), not by how the position was opened. It carries a per-direction rapid-nanpin brake (`RapidAddMaxCount`/`RapidAddWindowMinutes`/`RapidAddPauseHours`). There are no entry-side inputs (direction switch, entry line/filter, distance/limit, entry email) — a basket at `count == 0` simply has nothing to manage until an external position carrying `MagicNumber` appears. `OnInit` rejects a non-positive `LotMultiplier`/`GridStepMultiplier`, negative `MaxGridLevels`, negative `RapidAddMaxCount`/`RapidAddWindowMinutes`/`RapidAddPauseHours`, `RapidAddMaxCount > 0` with `RapidAddWindowMinutes <= 0`, or trading hours outside 0–23
- `DailyFadeBasket.mq5` — Market-order martingale averaging-basket EA (see **Basket Engine Architecture**) whose level-0 entry trigger is a **daily reference-price straddle** (no EMA/indicator): `UpdateReference()` captures the open of the `PERIOD_H1` bar starting at `ReferenceHour:00` (server time, default `1`) once per calendar day into `referencePriceInt` — captured the instant that bar begins forming, not at its close; `referenceReady` only ever goes false→true, on the very first successful capture, so a fresh start immediately catches up with the open of the most recent `ReferenceHour` bar (today's if already opened, otherwise yesterday's) instead of waiting for the next occurrence. Once `referenceReady`, `HasReachedEntryDistance()` gates a side's level-0 open (fade entry) whenever that side's basket count is `0`: price must be at/below the reference minus `BuyEntryDistancePips` before the buy basket opens, and at/above the reference plus `SellEntryDistancePips` before the sell basket opens — each defaulting to `0`, which requires price to have merely reached the reference price itself (buy: at/below it, sell: at/above it) rather than opening unconditionally. `BuyEntryDistancePips`/`SellEntryDistancePips` may also be negative, which relaxes the gate to allow that side's level-0 entry before price reaches the reference (buy: up to `|BuyEntryDistancePips|` pips above the reference; sell: up to `|SellEntryDistancePips|` pips below it). This gate is re-checked every time a side's basket count returns to `0`, not just once per day: a basket that closes on its TP/SL can reopen immediately, the same day, if the (still unchanged, since `referencePriceInt` only refreshes at the next `ReferenceHour`) gate still holds. The two sides are independent and need not fire together; each opens at the market price current on the tick its own gate first passes. From there each basket nanpins (grid/martingale adds) against its own adverse move exactly as in the shared engine. `ReferenceMaxDistancePips` (default `0` = no limit) is a separate **nanpin stop-distance filter**: `IsWithinReferenceDistance()` suspends further grid-level additions once price has moved more than that many pips away from this side's **entry basis** (either direction) — the entry basis is `referencePriceInt` adjusted by that side's entry distance (`referencePriceInt − BuyEntryDistancePips` for buy, `referencePriceInt + SellEntryDistancePips` for sell), i.e. the same price level `HasReachedEntryDistance()` requires price to reach before level 0 may open, not the raw `referencePriceInt` — the level-0 entry and basket TP/SL closing are unaffected. **Pyramiding**: independently of the nanpin grid, `ManageBasket()` also adds levels in the basket's *favorable* direction once price clears `favorableExtremePriceInt` (the best open price already in the basket, tracked alongside the nanpin grid's adverse-extreme price in the same `CollectBasketData()` pass) by `PyramidStepPips × PyramidStepMultiplier^(level−1)` (`CalculatePyramidStepPrice()`), lot `cachedLotSize × PyramidLotMultiplier^level` (`CalculatePyramidLotSize()`) — each add tagged with a `"Basket P%d"` order comment (vs. nanpin's `"Basket L%d"`) so `CollectBasketData()` counts pyramid adds (`buyPyramidCount`/`sellPyramidCount`) separately from nanpin adds; `ManageBasket()` then uses `count − pyramidCount` as the nanpin-only level count, so pyramid adds never inflate the nanpin step/lot progression or its own `MaxGridLevels` cap. `BuyPyramidMaxLevels`/`SellPyramidMaxLevels` (each default `0` = disabled) cap pyramid levels per side independently of the nanpin cap; pyramid adds are not gated by `IsWithinReferenceDistance()` (a nanpin-only stop-distance filter) but do respect `IsWithinTradingHours()`/`IsSpreadAllowed()`. It also carries a **time-window profit close**: `IsWithinProfitCloseWindow()` (server time, `ProfitCloseStartHour`/`ProfitCloseEndHour`, wraps past midnight if start > end, start == end disables it — same convention as `TradingStartHour`/`TradingEndHour`) gates an extra exit that closes a basket once its volume-weighted average pips profit reaches that side's `GetProfitCloseTargetPips(isBuy)` (`BuyProfitCloseTargetPips`/`SellProfitCloseTargetPips`, each default `10`; no "0 = disabled" sentinel — any integer including `0` or negative is a valid, always-active target, so a negative value closes the basket even at a loss; the only way to disable the profit close is `ProfitCloseStartHour == ProfitCloseEndHour`, which disables it for both sides), independent of `BuyBasketTakeProfitPips`/`SellBasketTakeProfitPips`/`BasketStopLossPips` and not gated by `TradingStartHour`/`TradingEndHour`. Unlike the shared engine's single `BasketTakeProfitPips`, this EA has no common basket take-profit input: `GetBasketTakeProfitPips(isBuy)` returns `BuyBasketTakeProfitPips`/`SellBasketTakeProfitPips` directly (each default `100`, `0` = disabled), with no common fallback. It likewise has no common `MaxGridLevels`: `GetMaxGridLevels(isBuy)` returns `BuyMaxGridLevels`/`SellMaxGridLevels` directly (each default `16`, `0` = unlimited), with no common fallback. `BasketStopLossPips` stays a single common value (no per-direction override). It has no rapid-nanpin brake (unlike the other Basket Engine EAs). `EnableBacktestCompleteNotification` (default `false`) sends one `SendNotification()` push notification (terminal push notifications, Tools > Options > Notifications) once an entire Strategy Tester **optimization** run finishes, via `OnTesterDeinit()` guarded by `MQLInfoInteger(MQL_OPTIMIZATION)` — a plain (non-optimization) single backtest never notifies, and an optimization with many parameter combinations notifies exactly once, not per pass. It has no effect outside the Strategy Tester. `OnInit` rejects `ReferenceHour` outside 0–23, a negative `ReferenceMaxDistancePips` (`BuyEntryDistancePips`/`SellEntryDistancePips` may be negative), `ProfitCloseStartHour`/`ProfitCloseEndHour` outside 0–23 (`BuyProfitCloseTargetPips`/`SellProfitCloseTargetPips` may be negative), a negative `BuyBasketTakeProfitPips`/`SellBasketTakeProfitPips`, a non-positive `LotMultiplier`/`GridStepMultiplier`, negative max-levels values, a negative `PyramidStepPips`, a non-positive `PyramidStepMultiplier`/`PyramidLotMultiplier`, negative `BuyPyramidMaxLevels`/`SellPyramidMaxLevels`, or trading hours outside 0–23. `MagicNumber` defaults to `8060`
- `DailyBreakoutBasket.mq5` — Fork of `DailyFadeBasket.mq5` with the entry direction fixed to trend/momentum instead of exposing an `EntryMode` input: `HasReachedEntryDistance()` opens the buy basket once price has moved `BuyEntryDistancePips` **above** the daily reference price and the sell basket once price has moved `SellEntryDistancePips` **below** it (price up → buy, price down → sell — the mirror of `DailyFadeBasket.mq5`'s default fade behavior), and `IsWithinReferenceDistance()`'s nanpin stop-distance entry basis is adjusted the same way (`referencePriceInt + BuyEntryDistancePips` for buy, `referencePriceInt − SellEntryDistancePips` for sell). It additionally caps how far price may already have run past that entry trigger price before a fresh basket is still allowed to open: `BuyEntryMaxDistancePips`/`SellEntryMaxDistancePips` (each default `0` = no limit) — once price is more than that many pips beyond the trigger price (`referencePriceInt ± EntryDistancePips`), `HasReachedEntryDistance()` treats the breakout as already missed and skips that side's level-0 entry until a later tick brings it back within range; an already-open basket's nanpin/pyramid adds and TP/SL closing are unaffected. Everything else — the reference-price capture, nanpin/pyramid grid engine, basket TP/SL, time-window profit close, per-direction TP/max-levels resolvers — is identical to `DailyFadeBasket.mq5`; see that entry for the full behavior. `OnInit` additionally rejects a negative `BuyEntryMaxDistancePips`/`SellEntryMaxDistancePips`. `MagicNumber` defaults to `8080`
- `ModifyTakeProfit.mq5` — EA to bulk-modify TP on open positions
- `SharpMoveAlert.mq5` — EA that sends a notification on a sharp price move; runs on M1
- `NewsFadeBasket.mq5` — Continuous dual-basket mean-reversion grid keyed off a news-release reference: a live pre-release Bid snapshot (taken `PreEventSnapshotMinutes` before a scheduled `EventHour:EventMinute` release, recurring daily) instead of a bar open. A buy basket opens when price is `MoveThresholdPips` below the reference, a sell basket the same distance above; each basket adds grid/martingale levels against adverse moves and is closed as a whole once its volume-weighted average pips profit reaches its effective take-profit target (or the loss reaches `-BasketStopLossPips`, as in the shared basket engine). **Take-profit decay**: `GetEffectiveTakeProfitPips(count)` reduces `BasketTakeProfitPips` by `TakeProfitStepPips` for each nanpin (grid) add already made — level 0 itself doesn't count, so the first reduction only applies once a level-1 add has happened — floored at `BasketTakeProfitMinPips` (default 2); `TakeProfitStepPips` (default 0) disables the decay (flat `BasketTakeProfitPips` throughout), and `BasketTakeProfitPips == 0` stays fully disabled regardless of count. `BasketStopLossPips` is unaffected. A new basket's level-0 entry may only open within `DetectionWindowMinutes` after the event time, off today's fresh snapshot, and only while `OpenMode` (`ENUM_OPEN_MODE`: buy & sell / buy only / sell only / none) allows that side to open. `OnInit` additionally rejects a negative `TakeProfitStepPips`/`BasketTakeProfitMinPips`
- `PositionSummary.mq5` — Script to print grouped position totals

MQL5 files must be compiled in MetaTrader 5 (MetaEditor, F7). No standalone build system.

## Basket Engine Architecture

`CloseOnlyBasket.mq5`, `NewsFadeBasket.mq5`, `DailyFadeBasket.mq5`, and `DailyBreakoutBasket.mq5` share a common **market-order martingale averaging-basket engine**; each swaps only its level-0 entry trigger (`CloseOnlyBasket.mq5` has none, `NewsFadeBasket.mq5` additionally swaps the reference-price source, `DailyBreakoutBasket.mq5` is `DailyFadeBasket.mq5` with the entry direction fixed to trend instead of fade — see each one's own section below). This section describes the shared engine; each EA's own section/file-list entry describes only what differs.

### Strategy

- **No price range/boundaries** — a basket's first position (level 0) opens immediately at market once that EA's entry trigger allows, rather than seeding a fixed-range grid of pending orders.
- **Grid / martingale adds**: each time price moves `GridStepPips` further against the basket's extreme entry, a new market order is added, lot size scaled by `LotMultiplier` to the power of the basket's position count (martingale-style). `GridStepMultiplier` (1.0 = fixed step) widens the required move for each successive level — the gap before adding level N is `GridStepPips × GridStepMultiplier^(N-1)`.
- **Lot sizing**: fixed `LotSize` base (clamped to the symbol's volume step/min/max at `OnInit`), scaled by `LotMultiplier^level`. There is no equity-derived (`UseAutoLot`) base.
- **Per-direction grid-level cap**: a common `MaxGridLevels` (`0` = unlimited) joined by `BuyMaxGridLevels` / `SellMaxGridLevels` (default `0` each). `GetMaxGridLevels(isBuy)` resolves the effective cap: the direction's override when it is `>=1`, otherwise the common value (so `0` on the override side = defer to common, `0` on both = unlimited). Once capped, no new levels are added but the basket is still monitored for TP/SL.
- **Basket exit**: the whole basket (all positions of one direction, same symbol/magic) is closed together via `trade.PositionClose()` once its volume-weighted average pips profit — Σ((currentPrice − openPrice) × direction × volume) / Σvolume, in pips — crosses `BasketTakeProfitPips` or `-BasketStopLossPips` (each `0` = that side disabled). This is not raw money P/L: it is unaffected by contract size / tick value and weights each position by lot size. There is no per-order TP/SL.
- Buy and Sell baskets run independently. `BuyOpenNew`/`SellOpenNew` gate only the level-0 position that starts a new basket: when a side is `false`, `ManageBasket()` still runs for it so an already-open basket on that side keeps averaging down and closes on its TP/SL (close-only), but no fresh basket is opened. After a basket closes it reopens automatically at market on the next tick (position count back to 0) as long as the side still allows opening new baskets and that EA's entry trigger agrees.
- `BuyUpperLimitPrice`/`SellLowerLimitPrice` (0 = no limit) cap where the level-0 position may open (buy at/below its upper limit, sell at/above its lower limit); grid adds, existing positions, and basket TP/SL closing are unaffected.
- `MaxSpreadPips` (0 = no limit) blocks new entries (initial or added grid level) when `SYMBOL_SPREAD` exceeds it; existing positions and basket TP/SL closing are unaffected.
- `TradingStartHour`/`TradingEndHour` (server time, hour granularity, both 0 = no restriction) block both new entries and basket TP/SL closing outside the window. Start == end = no restriction; start > end wraps past midnight (e.g. 22–6).
- `BuyOpenNew`/`SellOpenNew` (default `true`) are the per-direction open/close-only switch: `false` blocks only the level-0 position that would start a new basket, while leaving grid-level additions to an existing basket and basket TP/SL closing unaffected — stops opening new baskets while letting existing ones average down toward their exit. (There is no separate `BuyEnabled`/`SellEnabled` or `BuyCloseOnly`/`SellCloseOnly` input.)
- `OnInit` always rejects a negative `MaxGridLevels`/`BuyMaxGridLevels`/`SellMaxGridLevels`, a non-positive `LotMultiplier`/`GridStepMultiplier`, or trading hours outside 0–23; each EA layers its own entry-trigger validation on top (see its own section). Both `BuyOpenNew`/`SellOpenNew` `false` is allowed — a pure close-only wind-down of open baskets. Each EA has its own `MagicNumber` default — see the file list above.

### Event Flow

- **OnTick()**: runs on every tick (not gated to new bar, since basket TP/SL and grid-level triggers need intra-bar responsiveness) → `ManageBasket(true)` and `ManageBasket(false)` unconditionally. `ManageBasket()` itself checks `BuyOpenNew`/`SellOpenNew`: a close-only side opens no level-0 basket but still manages an open one.

## News Fade Basket Architecture

### Strategy

`NewsFadeBasket.mq5` is a **continuous dual-basket mean-reversion grid** keyed off a news-release reference price: a buy basket opens once price has moved a set distance below the reference, a sell basket the same distance above, each averaging down with grid/martingale adds and closed as a whole on its volume-weighted basket P/L.

- **Reference snapshot**: `UpdateReference()` runs each tick. `ComputeEventTime()` combines today's date with `EventHour`/`EventMinute` (server time, recurs daily); a change vs the stored `currentEventTime` marks a new day and clears `capturedToday`/`referenceFresh`. Once per day, in the window `[currentEventTime − PreEventSnapshotMinutes, currentEventTime)`, the current Bid is captured into `referencePriceInt` and both `capturedToday` and `referenceFresh` latch true. If that window has already passed when `UpdateReference()` first runs today (EA started or restarted after the release), the snapshot is skipped and `referenceFresh` stays false, so **no new basket opens today**. `referencePriceInt` / `capturedToday` / `referenceFresh` / `currentEventTime` are the EA's only session state and every one serves **only the level-0 entry trigger** — an open basket is managed entirely from its own positions, so a restart with a basket open is safe with no recovery code. There is no bar-open reference and no H1-timeframe assumption — the reference is always a live Bid snapshot.
- **Detection window**: a new basket's level-0 entry may open only while `now ∈ [currentEventTime, currentEventTime + DetectionWindowMinutes]` (`IsWithinDetectionWindow()`), **and** `referenceFresh`, **and** `OpenMode` (`ENUM_OPEN_MODE`, default `OPEN_MODE_BOTH`) allows that side to open: `OPEN_MODE_BOTH` allows both, `OPEN_MODE_BUY_ONLY`/`OPEN_MODE_SELL_ONLY` allow only that one side (the other side's already-open basket still winds down), and `OPEN_MODE_NONE` allows neither — a pure close-only wind-down of any open baskets on both sides. In every case only that side's `count == 0` level-0 trigger is skipped; grid adds to an already-open basket and the basket-P/L exit are **not** gated by `OpenMode`, so a basket opened late in the window is still averaged down and closed afterwards, even across midnight.
- **Baskets**: `ManageBasket(true)` / `ManageBasket(false)` both run every tick unconditionally in `OnTick()`; the level-0 check inside `ManageBasket()` reads `OpenMode` for the given direction (an excluded side still manages an open basket). Each direction compares against one `currentPriceInt` — Ask for buy, Bid for sell — used for the level-0 trigger, the grid-add trigger, and the pips-P/L calc alike. **Buy basket**: opens level 0 when Ask ≤ `referencePriceInt − MoveThresholdPips` (within the window); re-opens on the next qualifying drop while still in the window. **Sell basket**: mirror — opens when Bid ≥ `referencePriceInt + MoveThresholdPips`. Both share one `MagicNumber` (default `9001`), distinguished by `POSITION_TYPE`, and are managed independently. New entries (level 0 and grid adds) are gated by `MaxSpreadPips`; the basket-P/L close is not.
- **Grid/martingale**: `CalculateGridStepPrice(count)` = `GridStepPips × GridStepMultiplier^(count−1)` further against the basket's extreme entry adds a level, lot `× LotMultiplier^count` (via `CalculateLotSize()`, clamped to the symbol's volume step/min/max), capped by `MaxGridLevels` per basket (**required, > 0** — no unlimited mode; the basket is still monitored for the exit once capped).

### Exit

The same volume-weighted basket-P/L exit as the shared **Basket Engine Architecture** — no reversion-to-reference check and no per-order TP/SL:

- `GetBasketPositionTicket(i, isBuy)` is the single place the basket filter lives (this symbol + this magic + the given direction) — returns the ticket of the now-selected position, or 0. Both `GetBasketStatus()` and `CloseBasket()` iterate `PositionsTotal()` through it.
- `GetBasketStatus()` computes the basket's position count, extreme open price, and **volume-weighted average pips profit** — Σ((currentPrice − openPrice) × direction × volume) / Σvolume / `pipFactor`. No account-currency P/L is tracked; the close log reports pips only.
- **Take-profit decay**: `GetEffectiveTakeProfitPips(count)` reduces `BasketTakeProfitPips` by `TakeProfitStepPips` (default 0 = no decay) for each nanpin add already made — level 0 doesn't count, so the first reduction only kicks in once a level-1 add has happened — floored at `BasketTakeProfitMinPips` (default 2 pips). `BasketTakeProfitPips == 0` stays disabled regardless of count.
- `ManageBasket()` closes the whole basket via `CloseBasket()` (`trade.PositionClose()` per position) once `pipsProfit >= GetEffectiveTakeProfitPips(count)` or `pipsProfit <= -BasketStopLossPips` (each `0` = that side disabled; `BasketStopLossPips` defaults to 500). `BasketStopLossPips` is untouched by the decay.
- **No per-order TP/SL**: `OpenGridLevel()` sends `Buy`/`Sell` with `0, 0` for SL/TP. The basket is only ever acted on as a whole and only while the EA is online. A basket that reaches neither threshold stays open indefinitely by design (no max-hold).

### Event Flow

- **OnTick()**: `UpdateReference()`, then `ManageBasket(true)` and `ManageBasket(false)` unconditionally (the `count == 0` branch checks `OpenMode`). There is no `referencePriceInt <= 0` early return — unnecessary since `referenceFresh` already gates level-0 entry and an open basket never reads `referencePriceInt`. Runs every tick (not gated to new bar) since grid triggers and the basket-P/L exit need intra-bar responsiveness. No `OnTrade` handler.
